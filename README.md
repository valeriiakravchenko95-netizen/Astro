# Ядро астрологических расчётов

Автономный расчёт натальной карты: положения тел, дома, аспекты,
управители и диспозиторы. Только математика, никакого ИИ — на выходе
чистые цифры, интерпретация делается отдельно.

Работает полностью офлайн: эфемериды читаются с диска, шкала времени и
модель нутации встроены в Skyfield, часовые пояса берутся из базы IANA.
Телеграм-слой навешивается поверх этого ядра позже.

## Установка

```bash
pip install -r requirements.txt
python3 scripts/fetch_ephemeris.py     # положит de440s.bsp в ephemeris/
```

Эфемериды в репозиторий не входят и качаются отдельно: `de440s.bsp`
(1849–2150) весит 32 МБ и в git кладётся как обычный файл, полный
`de440.bsp` (1550–2650) весит 114 МБ и требует Git LFS. Подробности — в
[`ephemeris/README.md`](ephemeris/README.md).

## Как считать

```bash
python3 -m astro "1987-07-14 11:25" 50.4501 30.5234 --place Киев
python3 -m astro "1987-07-14 11:25" 50.4501 30.5234 --json
python3 -m astro "1987-07-14 11:25" 50.4501 30.5234 --houses whole_sign --minor
python3 -m astro "1987-07-14 11:25" 50.4501 30.5234 --orb square=6 --orb trine=6
```

Часовой пояс определяется по координатам; если в документах записано
смещение, его можно задать прямо: `--utc-offset 4`. Спорный час осеннего
перевода стрелок разрешается ключом `--fold 0|1`.

Из Python:

```python
from datetime import datetime
from astro import compute, Place

chart = compute(datetime(1987, 7, 14, 11, 25), Place(50.4501, 30.5234, "Киев"))
print(chart.position("sun").sign, chart.position("sun").house)
print(chart.primary_houses.cusps)
print(chart.to_dict())            # без даты и места рождения
```

## Что внутри

| Модуль | Отвечает за |
|--------|-------------|
| `astro/ephemeris.py` | ядро JPL, видимые геоцентрические положения |
| `astro/nodes.py` | средний и истинный Узел, нисходящий Узел, средняя Лилит |
| `astro/lots.py` | секта карты и Часть Фортуны |
| `astro/smallbody.py` | эфемериды малых тел, Хирон |
| `bot/` | телеграм-слой: диалог, поиск места, оформление |
| `web/` | страница: тот же расчёт в браузере, темы и трактовки |
| `astro/angles.py` | наклон эклиптики, RAMC, ASC, MC, Вертекс |
| `astro/houses.py` | целые знаки, Плацидус, Порфирий |
| `astro/aspects.py` | аспекты, орбисы, схождение и расхождение |
| `astro/rulers.py` | управители, достоинства, триплицитеты, термы, деканы, диспозиторы |
| `astro/patterns.py` | аспектные фигуры, стеллиумы, антисы |
| `astro/timeutil.py` | местное время → UTC |
| `astro/chart.py` | сборка карты и выдача результата |

Координаты — видимые геоцентрические, в истинной эклиптике и равноденствии
даты, то есть тропический зодиак со световым временем, аберрацией и
нутацией. Это та же система, в которой работают астрологические эфемериды.

Скорость по долготе считается численно, а не берётся из вектора состояния:
нужна производная именно видимой долготы, в которую входит и движение
самой системы координат. Отсюда же берётся признак попятного движения.

Дома Плацидуса ищутся итеративно из определения — деления суточного пути
точки на три равные по времени части. Промежуточные куспиды 11, 12, 2 и 3
считаются напрямую, остальные получаются как противоположные точки.

## Проверки

282 теста, `python3 -m pytest`. Проверяется не совпадение с чужой
программой, а физика, измеримая независимо от этого кода:

* **Моменты равноденствий и солнцестояний** сходятся с опубликованными
  таблицами в пределах минуты и с `skyfield.almanac`, который ищет их
  своим трактом, — в пределах секунды.
* **Длина тропического года** (365.2422 суток), **синодического месяца**
  (29.5306) и **период обращения узла** (18.6 года) выходят из расчёта
  сами.
* **ASC, MC и Вертекс** переводятся обратно в высоту и азимут другим
  путём: Асцендент обязан лежать на горизонте в восточной половине, MC —
  на меридиане, Вертекс — на главном вертикале ровно в азимуте 270°.
  Проверено на шести местах обоих полушарий, включая Мурманск.
* **Куспиды Плацидуса** проверяются по своему определению, измеренному
  через реальное время: моменты восхода и кульминации ищутся численно по
  высоте, которую считает Skyfield, и куспид обязан делить получившуюся
  дугу в заданной пропорции.
* **Часовые пояса** проверены на советских датах: 1925 год — UTC+2,
  декретное время с 1930-го — UTC+3, декретное с летним в 1981-м — UTC+4,
  постоянное время 2011–2014 — UTC+4, Ташкент 1975-го — UTC+6.

## Страница в браузере

Расчёт целиком перенесён в браузер: страница в [`web/`](web/) считает
карту сама, без сервера. Ссылку на неё можно ставить в шапку профиля, а
дата и место рождения при этом физически не покидают устройство
посетителя — отправлять их некуда.

```bash
cd web && python3 -m http.server 8000   # посмотреть локально
```

Публикуется на GitHub Pages рабочим процессом
[`.github/workflows/pages.yml`](.github/workflows/pages.yml); включить
нужно один раз в настройках репозитория. Подробности, ограничения и
порядок пересборки данных — в [`web/README.md`](web/README.md).

Перенос сверен с этим ядром на четырёхстах картах по обоим полушариям и
по столетию: долготы расходятся не более чем на девять десятых угловой
секунды, углы и куспиды — на три десятых, а дома, аспекты, фигуры,
достоинства и диспозиторы совпадают полностью.

## Телеграм-бот

В этом репозитории лежит код бота. Самого бота в Telegram он не создаёт —
учётную запись бота регистрирует @BotFather, и сделать это может только
владелец аккаунта.

**1. Завести бота в Telegram.** Написать [@BotFather](https://t.me/BotFather),
команда `/newbot`. Он спросит отображаемое имя (любое, например
«Натальная карта») и адрес, который обязан оканчиваться на `bot`
(например `my_natal_chart_bot`). В ответ придёт токен вида
`123456789:AAxxxxxxxx…`. Токен — это пароль от бота: его не выкладывают в
репозиторий и никому не пересылают. Если он всё же утёк, у @BotFather
есть `/revoke`.

**2. Положить токен в настройки.**

```bash
cp .env.example .env
# вписать туда свой токен
```

Файл `.env` в репозиторий не попадает — он в `.gitignore`.

**3. Поставить зависимости и эфемериды.**

```bash
pip install -r requirements-bot.txt
python3 scripts/fetch_ephemeris.py
python3 scripts/fetch_chiron.py       # по желанию
```

**4. Запустить.**

```bash
python3 -m bot
```

Бот отвечает, покапроцесс жив. Закрыли терминал — замолчал. Для
постоянной работы нужна машина, которая не выключается: любой VPS, где
процесс поднимается службой systemd, или домашний компьютер, который
всегда включён. Никакого внешнего адреса и сертификата не требуется —
бот сам опрашивает Telegram, а не принимает входящие соединения, так что
за NAT он тоже работает.

Бот спрашивает дату, время и место, после чего отдаёт карту: положения,
углы и дома, аспекты, достоинства, фигуры, диспозиторы. Разделы
открываются кнопками, чтобы не заваливать чат простынёй.

Место ищется офлайн, по выгрузке GeoNames в пакете `geonamescache` —
включая написание по-русски. Когда название неоднозначно (Донецк есть и
на Украине, и в России), бот показывает варианты с населением, а не
выбирает молча. Можно прислать координаты или геопозицию.

Если время рождения неизвестно, карта считается на полдень, но дома и
Асцендент не показываются вовсе, и об этом сказано прямо: выдавать за
расчёт то, что определяется минутами рождения, нельзя.

**Данные рождения бот не хранит.** Дата, время и место живут в памяти
процесса только до конца расчёта — дальше состояние очищается, и остаются
лишь готовые тексты разделов и идентификатор карты. На диск не пишется
ничего, в журнал попадает только тип ошибки, без введённых значений. Это
проверяется тестом: после расчёта в состоянии диалога не должно
находиться ни года рождения, ни координат.

Настройки читаются из `.env` рядом с проектом либо из переменных
окружения, причём окружение имеет приоритет — на сервере удобнее задавать
всё им. Список настроек с пояснениями — в `.env.example`.

## Что стоит знать

**У средней Лилит две модели, и выбор не косметический.** Простой полином
(долгота перигея плюс полуоборот, Meeus гл. 47) и тот же полином с рядом
периодических поправок расходятся между собой до 7 угловых минут. По
умолчанию считается модель `swiss` — она совпадает со средним апогеем
Swiss Ephemeris и построенных на нём программ с точностью около 0.6″ на
интервале 1850–2150. Простой полином доступен ключом `--lilith meeus`.
Коэффициенты ряда получены разложением расхождения по средним аргументам
лунной теории; это числовые коэффициенты физической величины, кода Swiss
Ephemeris в них нет, и самой библиотеки среди зависимостей тоже.

**Средний Узел оставлен на простом полиноме** и расходится со Swiss
Ephemeris до 19″. Истинный Узел расхождений не даёт вовсе — он
определяется геометрией мгновенной орбиты, а не выбором полинома, и
именно его показывает большинство программ.

**Плацидус за полярным кругом не существует.** Там часть эклиптики не
восходит и не заходит, делить нечего. Код это обнаруживает и отказывается
считать, вместо того чтобы молча подменить систему; подменить можно явно —
ключом `--house-fallback whole_sign` или `porphyry`.

**Хеш карты без соли персональные данные не скрывает.** Пространство дат и
мест мало, и SHA-256 от даты рождения с координатами перебирается за
минуты. Задавайте `ASTRO_HASH_SALT` — иначе идентификатор годится только
как ключ кеша, но не как обезличивание.

**Внешних планет у ядра нет на уровне центра планеты** — DE440 даёт
барицентры их систем. Смещение в геоцентрической проекции меньше секунды
дуги; астрологические эфемериды поступают так же.

**Достоинства считаются во всех пяти разрядах**: обитель с экзальтацией,
триплицитет по Дорофею (или по Птолемею), египетские термы и деканы —
халдейские либо по стихии. Отсюда важное различие: тело без обители и
экзальтации ещё не перегрин, у него могут быть терм или декан. Настоящий
перегрин — тот, у кого нет ни одного из пяти.

**Фигуры настолько строги, насколько строги орбисы.** Большой трин,
тау-квадрат, большой крест, парус, йод, малый трин, мистический
прямоугольник и стеллиумы ищутся поверх уже найденных аспектов, поэтому
сузьте орбисы — и половина конфигураций рассыплется, это нормально.
Фигура, целиком вложенная в большую, отдельно не показывается: в парусе
нет своего большого трина. Пара лунных узлов из поиска исключена — они
всегда в точной оппозиции по построению, и любая планета в квадрате к ним
давала бы мнимый тау-квадрат.

**Часть Фортуны считается с учётом секты**: днём дуга отмеряется от
Солнца к Луне, ночью наоборот. Часть программ формулу для ночных карт не
переключает, и там жребий выйдет зеркальным.

**Хирон подключается отдельно.** В ядрах DE малых тел нет, а кернелы,
которые отдаёт JPL Horizons, идут в формате SPK типа 21, которого не
читают ни Skyfield, ни jplephem. Поэтому `scripts/fetch_chiron.py`
забирает у Horizons таблицу векторов состояния и сохраняет её в
`ephemeris/chiron.npz`; дальше `astro/smallbody.py` интерполирует её
кубическим Эрмитом. Точность конвейера проверена на Юпитере против ядра
DE: на шаге в 16 суток расхождение по долготе меньше тысячной доли
угловой секунды, а Хирон движется втрое медленнее. Файла нет — Хирон
просто не попадает в карту, расчёт от этого не ломается.

```bash
python3 scripts/fetch_chiron.py          # 1850-2150, около 300 КБ
```

**Селены нет и не будет.** У неё нет общепринятой эфемериды: каждая
программа считает по-своему, и совпасть с вашей я смогу, только если вы
скажете, по какому именно правилу она считается.

## Лицензии

Ядро использует только разрешительно лицензированное:

| Компонент | Лицензия |
|-----------|----------|
| Skyfield | MIT |
| jplephem | MIT |
| NumPy | BSD |
| timezonefinder | MIT |
| Эфемериды JPL DE440 | данные NASA/JPL, без ограничений |
| aiogram | MIT |
| geonamescache | MIT |
| Данные GeoNames | CC BY 4.0 — требуют указания источника |

Список городов взят из GeoNames и распространяется по лицензии CC BY 4.0:
она разрешает любое использование, включая коммерческое, но требует
указывать источник. Ссылка стоит в подвале страницы — убирать её нельзя.

Swiss Ephemeris не используется намеренно. Библиотека распространяется по
двойной лицензии: AGPL-3.0 либо коммерческая. AGPL требует открывать
исходники сетевого сервиса пользователям, а бот публичный и код закрытый —
значит, оставался бы только коммерческий вариант. Skyfield под MIT такого
требования не несёт.
