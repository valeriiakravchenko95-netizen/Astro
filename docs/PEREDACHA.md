# Передача разработчику: калькулятор натальной карты LUME

Здесь все, что нужно, чтобы встроить калькулятор в основной сайт или
поддерживать его отдельно. Технические подробности по разделам лежат в
`web/README.md` (устройство страницы) и `web/content/README.md` (тексты,
проверки, настройки).

Сейчас калькулятор работает здесь: https://valeri-lume.lumeself.workers.dev
Там же короткие ссылки под рилсы, например `/dengi` и `/polnolunie`.

---

## Что это

Бесплатная страница: человек вводит дату, время и место рождения и получает
натальную карту с разбором по темам, событиями неба и проверками под рилсы.
В конце страницы предложение консультации.

- **Расчет идет целиком в браузере посетителя.** Это JS-порт астрономического
  ядра по эфемеридам JPL, сверенный с Python-ядром (Skyfield) на тестовых
  картах. Дата и место рождения никуда не отправляются.
- **Сервер нужен для одного:** отдавать тексты трактовок по частям. Страница
  присылает список ключей вроде `planet_in_sign: sun.2`, данных рождения
  сервер не получает.
- **Тексты - авторская собственность.** Поэтому в браузер они целиком не
  попадают, их нет в собранных файлах `dist/`. Сервер отдает только тексты
  под одну карту, до 120 штук за запрос, и только своему сайту (проверка
  Origin).

## Три обязательных правила

1. **Тексты остаются на сервере.** Нельзя класть
   `web/content/interpretations.json`, `transits.json` или `checks.json` в
   публичные файлы, в CMS с открытым API или в бандл. Публичный
   `content/public.json` собирается сборкой без текстов.
2. **Персональные данные не хранятся.** Дата, время и место рождения не
   уходят на сервер, в аналитику или в логи. Если понадобится что-то
   сохранять, только результат расчета и хеш, без даты и места.
3. **Лицензии сторонних частей** соблюдаются, список в `LICENSE.md`.
   Нужна подпись GeoNames (CC BY 4.0) в подвале, она уже стоит. Шрифты
   Cormorant (OFL) и подмножество FreeSerif для астрологических символов
   (GPL с исключением для шрифтов) можно встраивать как есть.

## Как встроить в основной сайт: три варианта

**А. Отдельный поддомен. Проще всего, рекомендую.**
Например, `karta.сайт.com`. В Cloudflare: Workers & Pages → проект
`valeri-lume` → Settings → Domains & Routes → Add → Custom domain. На
основном сайте ставится обычная ссылка или кнопка. Код трогать не нужно,
кроме `SITE_URL` (см. ниже).

**Б. Раздел основного сайта через Cloudflare.**
Если основной сайт уже за Cloudflare, воркер вешается на маршрут вроде
`сайт.com/karta/*`. Тогда в сборке нужно поменять пути: сейчас страница
ждет, что она лежит в корне, короткие ссылки тоже считаются от корня.

**В. Перенос в другой стек** (свой хостинг, Next.js, Tilda и т.п.).
- Статика: содержимое `dist/` после сборки (`npm run build`). Это обычные
  HTML, JS, CSS, шрифты и бинарные таблицы эфемерид, фреймворк не нужен.
- Сервер: один эндпоинт `POST /api/texts`. Логика в `server/texts.js`,
  примерно 60 строк без зависимостей, переносится на любой Node-сервер или
  serverless-функцию. Короткие ссылки и подмена превью - в
  `server/pages.js`.
- Tilda и конструкторы без своего сервера подходят только для варианта А
  или iframe: в них тексты пришлось бы отдавать открыто, а этого делать
  нельзя.

## Сборка и проверка

Нужны Node 20+ и Python 3.11+. Python нужен только для тестов и для
пересборки данных.

```bash
npm install
npm run build                  # собирает dist/
npm run preview                # http://localhost:8788, со всем API как на проде
npx wrangler deploy --dry-run  # проверка перед выкладкой

pip install -r requirements-dev.txt
python3 -m pytest -q           # 298 тестов: расчет, JS против Python, тексты, бот
```

`SITE_URL` - адрес сайта для превью ссылок (og:image и т.п.). Задается
переменной окружения при сборке:
`SITE_URL=https://karta.сайт.com npm run build`. В Cloudflare это Settings →
Variables → Build variables.

Публикация сейчас: Cloudflare Workers с подключенным GitHub-репозиторием,
сборка `npm run build`, выкладка `npx wrangler deploy`. Настройки в
`wrangler.jsonc`.

## Где что лежит

| Путь | Что это |
|---|---|
| `web/` | страница: `index.html`, `style.css`, `app.js` и модули |
| `web/astro/` | расчет в браузере: время, углы, дома, аспекты, транзиты |
| `web/data/` | таблицы эфемерид на 1920-2035, города, календарь событий неба на 2025-2031 |
| `web/content/` | тексты и настройки, правятся без программиста (см. README там) |
| `web/content/site.json` | ник, ссылки на консультации, возраст детской версии и т.п. |
| `worker/index.js` | точка входа Cloudflare Worker |
| `server/` | API текстов и короткие ссылки |
| `scripts/build-site.mjs` | сборка `dist/` |
| `scripts/build_web_*.py` | пересборка таблиц эфемерид, городов и событий |
| `astro/` | Python-ядро расчета (эталон для сверки) |
| `bot/` | Telegram-бот на том же ядре (сейчас не запущен) |
| `tests/` | тесты |
| `docs/` | вычитка текстов и сценарии рилсов |

## Что можно менять свободно

- Дизайн: цвета заданы переменными в начале `web/style.css`, светлая и
  темная тема. Знак lume - `web/logo.svg`, иконки - `favicon.svg`,
  `apple-touch-icon.png`, превью ссылки - `preview.png`
  (`scripts/make_preview.py`).
- Тексты, темы, проверки, ссылки под рилсы: файлы в `web/content/`, без
  кода.
- Аналитика: в `site.json` поле `analytics_token` для Cloudflare Web
  Analytics. Любая другая аналитика допустима, если в нее не уходят дата и
  место рождения.

## Что лучше не трогать без астролога

Расчетную часть (`web/astro/`, `astro/`) и правила подбора текстов
(`web/readings.js`, `web/checks.js`). Там много астрологических решений:
система домов, орбисы, управители, возраст детской версии. Изменения там
сверяются тестами `pytest`.

## Срок годности данных

- Календарь событий неба посчитан на 2025-2031. Продлить:
  `python3 scripts/build_web_events.py` (нужны эфемериды,
  `python3 scripts/fetch_ephemeris.py`).
- Таблицы положений в браузере покрывают годы рождения 1920-2035.
